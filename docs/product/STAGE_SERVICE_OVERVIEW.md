# STAGE 서비스 개요 및 기능 정의

버전: v0.1  
작성일: 2026-07-29  
상태: MVP 기획 기준 문서

---

## 1. 서비스 개요

STAGE는 무대에 서고 싶은 사용자가 크루 모집과 이벤트를 발견하고, 개인 단위로 지원해 크루에 합류한 뒤, 연습과 운영을 거쳐 실제 공연 경험을 만들 수 있도록 지원하는 모바일 우선 서비스다.

초기 카테고리는 댄스다. 도쿄의 10대~30대 여성, 특히 K-POP 댄스에 관심이 있는 일반 사용자를 핵심 대상으로 한다.

---

## 2. MVP 목표

MVP는 다음 흐름이 실제로 완성되는 것을 목표로 한다.

> 크루 모집 발견 → 모집 상세 확인 → 개인 지원 → 리더 승인 → 크루 합류 → 연습 준비 → 이벤트 참가

MVP는 범용 SNS나 완전한 커뮤니티 플랫폼을 목표로 하지 않는다.

- 문의

### 6.3 지원

- 지원은 등록 사용자 개인 단위로 진행한다.
- 대표자가 여러 사람을 한 번에 지원하는 기능은 만들지 않는다.
- 친구와 함께 참가하려면 모집 링크를 공유하고 각자 가입·지원한다.
- 공유 링크로 들어온 미가입 사용자는 가입과 프로필 설정 후 원래 모집 상세로 복귀해야 한다.

### 6.4 지원 상태

상태:

- pending
- accepted
- rejected

사용자는 마이페이지에서 현재 지원 상태를 확인한다.

### 6.5 리더의 지원자 관리

- 지원자 목록
- 지원자 프로필
- 승인
- 거절
- 승인 시 크루 멤버십 생성 또는 활성화
- 중복 pending 지원 방지
- 탈퇴·제외 이후 재지원 지원

## 7. 크루

### 7.1 크루 수명주기

- 모집은 원칙적으로 하나의 목표 이벤트와 연결한다.
- 크루는 이벤트 종료 후에도 유지할 수 있다.
- 지속 크루는 다음 목표 이벤트를 선택할 수 있다.
- 과거 이벤트와 활동 이력은 보존한다.

### 7.2 크루 홈

표시 정보:

- 크루 프로필
- 현재 목표 이벤트
- 다음 연습
- 일정 투표
- 출결
- 공지
- 자료
- 스튜디오
- 멤버
- 지원자 관리
- 과거 활동

### 7.3 멤버

- active
- left
- removed
- leader/admin
- member

정확한 가까운 역 정보는 승인된 동일 크루의 active member에게만 제한적으로 표시한다.

### 7.4 리더 승계

MVP 구현 전 확정이 필요한 기본 원칙:

- active admin 또는 leader는 최소 1명 유지
- 유일 리더 탈퇴 전 권한 이전 필요
- 운영자 복구 시 audit 필요

## 13. 메시지

목적:

- 모집 전 문의
- 승인 전·후 필요한 1:1 연락
- 레슨·프로젝트 관련 제한적 문의

원칙:

- LINE 그룹채팅을 대체하지 않는다.
- 자유 DM보다는 모집·레슨 등 명확한 context가 있는 문의를 우선 검토한다.
- 차단 관계에서는 요청, 승인, 읽기, 전송 정책을 일관되게 적용한다.
- unread count를 제공한다.

## 18. 데이터·기술 기본 원칙

- 기존 `001`~`031` migration은 수정하지 않는다.
- 이후 변경은 신규 번호 migration으로 추가한다.
- `groups`는 당분간 기술명을 유지하고 UI에서 クルー로 표현한다.
- 기존 `parts`를 댄스 역할로 덮어쓰지 않는다.
- exact station은 public profile에서 분리한다.
- 민감 정보는 safe view/RPC를 통해 최소 필드만 반환한다.
- service role 또는 secret key를 Flutter에 넣지 않는다.
- Flutter Web과 미래 iOS 빌드를 함께 지원한다.
- Web 전용 API는 플랫폼 분기 파일이나 stub으로 격리한다.
- 신규 기능은 작은 단위로 구현하고 테스트한다.
